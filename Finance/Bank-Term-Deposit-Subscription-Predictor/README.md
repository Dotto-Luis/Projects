## 1. Business Goal

A Portuguese bank runs phone campaigns to sell term deposits. Calling everyone is expensive and most clients say no (only ~11% subscribe). The goal: **predict which clients are likely to subscribe before calling them**, so the campaign can prioritize high-probability leads and cut costs.

The key modeling decision in this project is **leakage handling**: the dataset's strongest feature, `duration` (call length), only exists *after* the call — exactly what the model is supposed to help avoid. Both scenarios are trained and reported to quantify the damage of using it.

---

## 2. About the Data

[UCI Bank Marketing dataset](https://archive.ics.uci.edu/dataset/222/bank+marketing) — 41,188 client contacts, 20 features:

- **Client attributes**: age, job, marital status, education, default, housing/personal loans.
- **Campaign attributes**: contact type, month, day of week, number of contacts, previous outcomes.
- **Economic context**: employment variation rate, consumer price index, euribor 3m, employees.
- **Target** `y`: subscribed to term deposit (yes/no) — imbalanced, 11.3% positive.

The CSV ships with the repo (`data/`, 5.6MB).

## 3. Usage Examples

```bash
# 1. Install dependencies (uses uv - https://docs.astral.sh/uv/)
uv sync

# 2. Train both models and write metrics.json
uv run python -m src.train
```

Using the modules directly:

```python
from src.data_prep import load_data, prepare_features, split_data
from src.train import build_models, evaluate

df = load_data()
X, y = prepare_features(df, drop_leaky=True)
X_train, X_test, y_train, y_test = split_data(X, y)

model = build_models()["hist_gradient_boosting"].fit(X_train, y_train)
print(evaluate(model, X_test, y_test))
```

Exploratory analysis: `notebooks/01_data_exploration.ipynb` and `notebooks/02_feature_engineering.ipynb`.

## 7. Results / Output

Test-set metrics (20% stratified hold-out), with the leakage comparison made explicit:

| Scenario | Model | ROC AUC | PR AUC | Recall | Precision |
|---|---|---|---|---|---|
| **Realistic (no `duration`)** | Logistic Regression | 0.801 | 0.460 | 0.64 | 0.37 |
| **Realistic (no `duration`)** | **HistGradientBoosting** | **0.818** | **0.492** | 0.65 | 0.41 |
| ⚠️ With leakage (`duration` kept) | HistGradientBoosting | 0.955 | 0.697 | 0.93 | 0.47 |

The leaky model looks spectacular (0.954 AUC) but is unusable: `duration` doesn't exist when deciding whom to call. The honest 0.815 AUC still delivers business value — with `class_weight='balanced'`, the model recovers ~65% of subscribers while calling a fraction of the list.
